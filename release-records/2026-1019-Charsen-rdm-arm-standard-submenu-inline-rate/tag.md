# RDM-ARM 1.2.1 —— 标准分辨率不再随刷新率消失，分辨率行自带刷新率

状态：**双源已发布**。`origin`（Gitee）与 `github` 的分支、tag、Release 与附件一致。

## 起因

1.2.0 发布后收到三连反馈，都发生在同一台电视上：

> 接上 Letv SuperTV，BetterDisplay 能设 60 Hz，你这里看不到。
> 改了分辨率之后又不能设 60 Hz 了，看不到这个选项。
> 我改了一下刷新率，又看不到那个新增出来的分组。

1.2.0 的补丁只解决了「60 Hz 在不在列表里」，没有解决「列表的形状会变」。
用户在 30 Hz 下靠「标准分辨率」子菜单找到 60 Hz 的 1080p，切过去之后同尺寸 HiDPI
也有 60 了，标准模式不再「更快」——于是那个子菜单连同刚找到的入口一起消失。
`30 Hz → 60 Hz → 30 Hz` 是用户的一次往返，而菜单把它当成了三个不同的世界。

同时还有一条独立缺陷：`allModes(includeUnusable:)` 在开关关着的时候仍然把私有表的
模式并了进来，菜单里出现点不动的行（CoreGraphics 1001）。

## 改了什么

| 位置 | 变化 |
| --- | --- |
| `StatusMenuBuilder.resolutionsItem` | 标准模式分组**无条件**生成，不再按「是否更快」决定存在与否 |
| `StatusMenuBuilder.modeItem` | 抽出的单行构造：标签写组内**最快**刷新率，点击也落到该模式 |
| `StatusMenuBuilder.refreshRateItem` | 改用未过滤的模式表；底部新增可点击跨界行 `60 Hz @ 1920 × 1080` |
| `DisplayMode.menuTitle(withFastestRate:)` | 新增；`menuTitle` 保持无刷新率 |
| `DisplayManager.allModes` | 私有表改由 `includeUnusable` 把关 |
| `Localization` | 新增「标准分辨率（非 HiDPI）」「%@ @ %@」；HiDPI 过滤提示改写 |
| `GUISelfTest` | 删掉「分辨率条目故意不写刷新率」的过期注释 |
| `README.md` | HiDPI 过滤段落按新行为重写 |

源文件数不变（27），命令行接口无变化。

## 屏幕上的样子

电视停在 `1920 × 1080 ⚡️ @ 30 Hz` 时，`--selftest` 的菜单转储（节选）：

```
分辨率
  2560 × 1440 ⚡️ · 30 Hz   → 2560 × 1440 ⚡️ @ 30 Hz  [5120 × 2880]
[x] 1920 × 1080 ⚡️ · 30 Hz  → 1920 × 1080 ⚡️ @ 30 Hz  [3840 × 2160]
  960 × 540 ⚡️ · 60 Hz    → 960 × 540 ⚡️ @ 60 Hz   [1920 × 1080]
- <separator>
  标准分辨率（非 HiDPI）
    1920 × 1080 · 60 Hz  → 1920 × 1080 @ 60 Hz  [1920 × 1080]
    1440 × 900 · 60 Hz   → 1440 × 900 @ 60 Hz   [1440 × 900]
    …
刷新率
[x] 30 Hz  → 1920 × 1080 ⚡️ @ 30 Hz  [3840 × 2160]
    25 Hz  → 1920 × 1080 ⚡️ @ 25 Hz  [3840 × 2160]
- <separator>
    60 Hz @ 1920 × 1080  → 1920 × 1080 @ 60 Hz  [1920 × 1080]
```

三处都指向同一个事实：这台电视的 60 Hz 只在 1× 1080p 时序里存在。以前要么看不到
（被 HiDPI 过滤），要么看到的分组会消失（按速度门控），要么看见了也点不动（私有表）。

### 不变量是怎么算的

菜单自己不对照自己。真值取自 `-lm --json` 的模式表，逐条重算菜单应当写什么：

| 断言 | 说明 |
| --- | --- |
| 几何一致 | 行标签的 `W × H ⚡️` == 点击后应用的几何 |
| 刷新率一致 | 行标签的 `· N Hz` == 点击后应用的 `N Hz` |
| **最快档** | 行标签的 `N Hz` == 模式表里该几何的**最大**刷新率 |
| 主列表 | HiDPI 过滤开启时不含任何 1× 行 |
| 标准子菜单 | 开关开启时**必须存在**，且 1× 几何集合与模式表完全相等（BenQ 23/23、电视 19/19） |
| 刷新率菜单 | 每行都属当前几何；恰好一个勾；跨界行不得更小、必须更快 |

第三行是关键：把标签从「最快档」改成「最慢档」，前两行依然全过——标签和落点会
一起变错，只有对照模式表才看得出来。

### mutation（每条都实测，不是设想）

| 变异 | 结果 |
| --- | --- |
| M1：`max` → `min`（行内标注最慢档） | **59 条失败**，如 `3360 × 1890 ⚡️ · 24 Hz: table's fastest ... is 60 Hz` |
| M2：标准分组改回「比同尺寸 HiDPI 更快才生成」 | **2 条失败**：BenQ `1 of 23`、电视 `3 of 19`；菜单行数 70 → 32 |
| M3：私有表门控改回 `if true` | **20 条失败**，全部是 `geometry absent from the table`（`800 × 450 ⚡️`、`672 × 504 ⚡️` …）；行数 70 → 101 |

M2 的数字就是这次的 bug 本身：旧逻辑下标准子菜单只剩 1 条（BenQ）和 3 条（电视），
用户看到的「分组消失」在测试里是可复现的 22 条缺失。

## 未验证 / 已知边界

- **不变量脚本没有入库**（`/tmp/rdm-menu-invariants.py`）。它依赖本机菜单文案
  （`分辨率` / `标准分辨率` / `→`）和固定的 defaults 域，直接放进仓库会在 CI 上
  变成又一份「本机绿、CI 红」。要入库得先把菜单文案从断言里解耦。
- **私有表记录仍在真值表之外**：`-lm --json` 不含私有记录，所以 M3 靠「菜单出现
  模式表里没有的几何」抓到它。这是间接证据，不是「私有记录被正确排除」的直接证明。
- **`--roundtrip` 只能验证一次往返**，无法覆盖「切到某个时序后模式表重新生成」的
  全部形状（本机可复现的 30/60 Hz 两个世界已覆盖）。

## 遗留（未修，已知）

1. `-r 60` 在没有 60 Hz 的尺寸上静默落到最接近的模式，`rc=0`。用户拿不到「这个尺寸
   做不到 60」的信号，`findMode` 是 best-effort 设计。修它会改变命令行的语义，留给
   下一个 minor。
2. 构建后仍会在 `build/RDM-ARM.app` 注册出第二个同名 app。`lsregister -u` 只能挡
   5–10 秒（Spotlight 会再登记）。根治要把开发副本改名成 `build/.RDM-ARM.app`
   ——点前缀路径不被 Spotlight 收录，实测有效——但改名牵动 `build.sh`、
   `package-release.sh` 与 4 处引用，没在这次发版里顺手做。
